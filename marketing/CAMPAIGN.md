# 근거

## 포지셔닝

**초등 1~6학년 연산 연습, 광고·결제·로그인 없이.** 종이 문제집을 부정하지 않는다 — *대체재가 아니라 워밍업*이다.

동명·유사명 앱 3개가 전부 평가 0건이므로 **이름으로 싸우지 않는다.** 식별은 세 축으로 한다:
부제의 학년 범위 · 첫 스크린샷 썸네일 · 평가 수 1건 이상.

**버린 타겟**: 개념·선행 학습 / iPad / 게임성 수요 / 5·6학년 심화. 전부 1★ 리뷰의 원천이라 스토어에서 먼저 밝혔다.

## 메시지 하우스 — 기둥 3개

| 기둥 | 약속 | 코드 근거 |
|---|---|---|
| **1. 요구하는 게 없다** | 광고·결제·로그인·권한 없음 | 광고 SDK 0건 · StoreKit 미사용 · Firebase 익명 인증 · Usage Description 0건 · **첫 실행 알림 권한 요청 제거** |
| **2. 한 판 20문제, 매번 새 문제** | 20문제·30초·난수 생성 | `GameSession.problemCount` · `ProblemGenerator` 매판 생성 |
| **3. 부모가 어디가 약한지 본다** | 연산별 정답률 | `ParentDashboardViewModel` — 최근 50판, **시도한 연산만** |

**기둥별 금지선**: 교육과정 연계 / 문제 N개 수록 / 프리미엄·구독 / iPad / AI·맞춤·분석·진단 / **속도 보너스** / 사회적 증거.
검수자가 전수 확인한 결과 **속도 보너스는 카피에 0건**이고, `보너스`/`bonus` 문자열이 ko·en·ja 어디에도 없어 스크린샷으로도 샐 수 없다.

## 시장 조사 요약

- 시장 전체 1순위 불만은 **광고** → 기둥 1의 근거
- 진짜 경쟁자는 다른 앱이 아니라 **종이 문제집·학습지** → 키워드에 부모의 언어(`문제집`·`학습지`·`예습`·`복습`)를 넣은 이유
- `나눗셈`·`분수`·`3학년 수학` 구간이 비어 있다(상위 앱들이 평가 0~2건) → 키워드 우선순위
- 교육 Top 100에 초등 연산 앱 0개 → **카테고리 순위를 목표에서 제외**

## 성공 지표 — 측정 수단이 있는 것만

제품 페이지 전환율 · 키워드 수기 검색 노출 · 평가 수(목표 5건) · Campaign Link별 유입 · 커뮤니티 게시 생존율(삭제·경고 0건).

**앱 내 행동(리텐션·완주율)은 측정하지 않는다.** 애널리틱스 SDK가 0건이고 `IS_ANALYTICS_ENABLED = False`다.
이것이 기둥 1의 근거이기도 하므로 **"측정하려고 SDK를 넣는" 교환은 하지 않는다.**

첫 30일은 목표 달성 기간이 아니라 **기준선 수집 기간**이다.

# 이 캠페인이 앱 코드를 바꾼 곳

마케팅 작업이 앱의 사실을 확인하는 과정에서 결함 5건이 나왔다. 전부 고쳤다.

| # | 결함 | 고친 곳 |
|---|---|---|
| 1 | 결과 화면의 `콤보` 칸이 최대 콤보가 아니라 **정답 개수**를 표시. `18/20 정답` 옆에 `x18 콤보`가 찍히는데 점수는 `maxCombo 11`로 계산돼 한 화면이 두 값을 말했다 | `ResultView.swift` |
| 2 | **첫 실행에 알림 권한을 무조건 요청.** 별명도 안 정한 아이에게 앱이 먼저 요구하는 장면 | `EveryDoMathApp.swift` — 요청 제거 |
| 3 | **게임이 끝날 때마다 매일 19시 알림을 예약.** 설정과 무관하게 동작했고 `isReminderEnabled`는 목표 알림만 감쌌다 | `ResultViewModel.swift` — 설정에 연결 |
| 4 | 알림을 꺼도 이미 등록된 스트릭 예약이 **다음 게임까지 살아남았다.** `cancelStreakReminder()`는 죽은 코드였다 | `LearningGoalRepository.swift` |
| 5 | 스트릭 알림 시각이 **19시 하드코딩.** 아침 8시로 맞춘 부모가 고른 적 없는 19시 알림을 매일 받았다 | `NotificationManager.swift` — 부모 설정 시각 사용 |

2~5번이 기둥 1("요구하는 게 없다")의 근거다. **카피를 고쳐서 닫을 수 없는 유일한 항목이었다.**

> `01_프로필설정.png`에 떠 있던 알림 팝업은 촬영 사고가 아니라 **출시 동작**이었다.
> 테스트에서 팝업을 닫는 것은 사용자가 보는 장면을 스크린샷에서만 치우는 일이었다.
> **스크린샷을 카피에 맞추자는 제안이 나오면, 그 카피가 틀린 것이다.**
